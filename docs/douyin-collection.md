# 抖音网页采集

本版本从用户可见的抖音网页发现视频来源，并尝试保存网页明确公开的可下载文件。无需抖音开放平台密钥。浏览器页面结构、登录状态和播放器实现会影响成功率；代码与模拟测试通过并不等于已经完成真实网站下载验收。

## 使用

1. 在工作台建立关键词采集任务，浏览器模式使用默认排序、不限发布时间、每次最多 10 条。默认定时周期为 6 小时。
2. 运行项目的“启动抖音采集.cmd”。它使用已安装的 Chrome 和项目专用 `data/douyin-browser`，与个人 Chrome 配置分开。
3. 在新窗口中本人完成登录和必要验证，回到启动窗口按回车。采集器随后领取工作台中的任务。
4. 如中途出现登录或验证，采集会暂停。本人完成后，在工作台重新运行失败任务，再按回车继续等待。
5. 下载文件位于 `data/collected/douyin`；选择需要使用的素材、核对授权后，再通过“采用采集素材.cmd”送入剪辑投递箱。

只准备登录会话可运行：

```text
python -m studio.browser_collector --login-only
```

运行依赖为 Python `playwright` 包及已有 Chrome；程序不读取个人 Chrome Cookie，也不导出登录凭据。专用配置目录只允许一个采集进程持有。

## 当前采集范围

- 从实际渲染的 `/video/<数字编号>` 链接收集来源；不调用隐藏搜索接口或解析签名。
- 优先使用可见“下载／保存本地”链接所公开的地址，其次使用可见 HTML 视频播放器的 `currentSrc` 或 `src`。
- 仅执行脚本、未公开地址的下载按钮，以及 `blob:` 播放器，当前可能只保存来源记录。程序不会绕过验证码、登录要求或下载限制。
- 视频地址和每次跳转均限定在受支持的公开 HTTPS 视频 CDN；不抓取任意第三方地址。
- 下载前要求明确文件大小，单文件不超过 128 MiB，使用 4 MiB 分段请求。浏览器请求接口会缓冲响应；不符合分段长度或范围的响应立即拒绝。
- 成品文件通过 ffprobe 检查后才发布为 `.mp4`。原字节不做去水印、裁切或再编码。
- 相同视频跨关键词或跨任务再次出现时，先核对已有文件与来源记录的大小、SHA256 和视频信息，通过后复用。校验失败不会覆盖原文件。

## 来源记录与采用

每条成功保存的素材对应 `<视频编号>.mp4` 与 `<视频编号>.provenance.json`，记录公开来源链接、关键词、标题、SHA256、文件大小、采集时间及 `rights_status: unknown`。不会把临时播放地址、Cookie 或整页响应写进来源记录。

公开可观看不代表可以商业复用。采集成功只表示本机保存了经检查的文件，尚未确认商用授权，也没有自动发送到企业微信。采集目录不能位于自动剪辑投递箱内。

中途验证导致任务失败时，此前已经处理的来源记录随失败状态同步到工作台，成功保存的文件和来源记录仍在本地，失败提示会说明保留数量。可在本地采用素材，或验证后重跑，已有文件会校验后复用。远程工作台只接收元信息，不会把本地下载状态冒充成远程服务器已验证的文件。

## 验证范围

测试使用模拟页面、模拟下载响应和临时文件，覆盖登录验证交接、来源地址检查、分段完整性、超大文件拒绝、去重缓存与篡改检查、投递箱隔离和配置锁。没有通过测试代码打开真实 Chrome 或发送真实下载请求；真实网页上的完整流程需另外验收。
