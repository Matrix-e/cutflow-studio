# 连接状态修复记录（2026-11-03）

用户观察到顶部显示「工作台已连接」，同时请求报错「GPU 暂未连接」。设置页还固定显示「已启用本地自动连接」，容易被理解为实时连通状态。

已确认的原因：部分操作失败只显示提示，没有更新全局状态；自动连接设置说明与实时状态混用；页面判定断线后，定时检查因为依赖 connected=true 而停止。旧代理把所有传输异常统一标为未连接，没有记录错误类型，所以无法还原截图那一次通信失败的具体原因。

排查时本机连接器、隧道、同步和远端服务均运行。直连与本地入口的状态、任务详情均成功返回；成片的分段读取正常。当时没有证据证明 GPU 停机。

修复原则：连接方式与实际状态分开显示；失败立即更新状态，继续进行只读检查；只有新一轮检查成功才恢复已连接；迟到的旧请求不能覆盖更新的故障状态；恢复时替换过时的连接错误提示。任务创建、审核和企业微信推送不会因连接恢复而自动重复提交。

本地代理区分超时、通信中断和服务不可用，并记录不含凭据的错误类型。可安全重试的读取请求最多重试一次；发布等写操作不自动重试。视频已开始传输后中断，也不会静默重复整个请求。

验证结果：160 项 Python 测试、13 项前端连接回归测试通过。已更新本地服务，在实际浏览器中打开已有 GPU 成片，视频成功加载，时长 5.533333 秒、无播放器错误；设置页显示本地页面状态、GPU 实际状态及最近检查时间。本次没有审核、发布或重建任何成片任务。

前端回归命令：`node --test tests/frontend_connection.test.js`。覆盖详情与视频读取失败、断线自动检查、过时响应、手动断开、凭据更新、业务校验错误、并发推送结果核实和错误提示恢复。
