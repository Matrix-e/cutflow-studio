# CutFlow Studio 研发架构与验收计划

第一批场景：口播、课程、访谈精剪；发布目的地：企业微信内部群机器人。v0.1 的目的，是把素材接收、任务恢复、可追溯剪辑、审片和受控发送做成可运行的闭环。正式商用画质和内容质量需要真实样片验收。

## 当前结构

```text
Windows 素材投递箱
  ├─ 文件稳定检测 → SHA-256 → SFTP 临时文件 → 远端校验 → 原子改名
  └─ 本机或 GPU 机器的目录观察器 → 带口令的任务 API
                                      ↓
                       SQLite 任务与事件记录
                                      ↓
                 原片分析 → 剪辑清单 EDL → FFmpeg 渲染
                                      ↓
                     成片检查 → 待审片 → 已确认
                                      ↓
                 企业微信上传 → 发送 → 发布回执与防重记录
```

界面只展示 API 返回的真实素材、任务、检查结果与发布状态。Sites 托管界面和本地控制台是入口；浏览器中的页面不能独立监控 Windows 文件夹，也不承担 GPU 推理。长期运行由本机同步进程和 GPU 工作进程负责。

## 组件责任

| 组件 | 当前责任 | 边界 |
| --- | --- | --- |
| `studio.sync` | 稳定文件检测、内容校验、SFTP 投递、已同步记录 | 需要用户的实际 SSH 接入信息与已核验主机密钥 |
| `studio.watch` | 监听可处理素材并提交任务 | 观察器必须保持运行；不会把上传中的临时文件当成素材 |
| `studio.server` | 访问口令、素材边界、任务 API、单工作进程锁 | 默认仅在本机回环地址监听；远程部署需要合适的 HTTPS 入口 |
| `studio.store` | SQLite 任务、状态转换、事件、去重与重启恢复 | v0.1 是单节点任务服务，未实现多租户分布式队列 |
| `studio.media` | 原片探测、保守静音剪切、显式 EDL、渲染、技术检查 | 不理解语义，不会自动判断重点、口误或论证结构 |
| `studio.transcribe` | 可选离线 ASR 命令，输出原片时间轴 SRT 与逐词 JSON | 需独立安装依赖并提供完整本地模型；未接入自动队列，未代表真实推理已验收 |
| `studio.delivery` | 企业微信官方接口上传、发送、防重复发布台账 | 用户需配置真实机器人地址；未配置时不发送 |

## 实际质量能力

现有引擎缩短较长静音，保留切点前后缓冲，避免为满足最短镜头而删除短语音。保留原始素材；每段源片入点、出点与成片时间可追溯。横竖画面适配采用等比缩放和留边，默认避免裁掉人脸。CPU 编码可用；选择 NVENC 后会探测，失败时回落并记下原因。输出使用 H.264/AAC MP4，支持声学响度处理。已有 SRT 可以按剪辑时间重映射。

检查包含可解码性、时长、画面尺寸、音视频流等可测指标。检查通过表示技术条件通过，不等同于内容节奏自然、字幕正确或商业表述准确。已有独立可选的离线转写命令，要求完整的本地模型，输出原片时间轴 SRT 与逐词 JSON，不会自动下载模型；尚未接入目录观察器和剪辑队列，也未完成真实模型推理验收。当前未实现说话人区分、语义删冗、错词重录拼接、人物跟踪重构图、风格一致的包装模板、完整黑场/冻结/音质评分和人工感知评分。

## 任务状态与恢复

```text
queued → analyzing → rendering → review → approved → publishing → published
                     ↓ failure                              ↓ uncertain
                    failed                                failed
```

相同素材版本与参数的进行中任务合并；观察器可提供幂等请求编号，避免重复扫描产生新任务。一个数据目录只允许一个工作进程持有系统锁。重启后分析/渲染中的任务回到队列；发布中断视为结果未知，不会自动再发。

`POST /api/jobs/{id}/retry` 仅重试失败的剪辑任务。出现过发布步骤的任务、发送结果未知的任务、已变化的原片都不会被此接口重排。企业微信发送台账和任务台账分别保留，官方返回成功后才记为已发布。

默认要求试看确认。明确启用自动发布模式后，观察器可按已选设置推进质量合格成片，但技术检查不能替代商业样片验收；应在确定的栏目、模板和素材条件下逐步放量。

## 商业化迭代里程碑

| 阶段 | 研发交付 | 进入下一阶段的验收条件 |
| --- | --- | --- |
| A：真实闭环 | 接入远程 GPU、真实目录和企业微信，运行服务重启与断网恢复 | 用获授权的真实样片完成同步、剪辑、审片、发送；逐项留存回执 |
| B：内容精剪 | 中文 ASR 与词级时间戳、说话人标签、语义段落、重复/口误候选、可修改 EDL | 人工逐句比对不漏词、不改意；每条删除都可追溯源片 |
| C：成片设计 | 不同课程/访谈模板、字幕规范、品牌片头片尾、音量与音乐混音、人物构图 | 小屏可读、关键人物完整、品牌色/字体一致；真实样片审美验收 |
| D：自动化质控 | 黑场/冻结/静音/削波/字幕溢出检测、内容置信度、异常回退 | 每类故障注入测试能拦截；低置信度自动进入审片队列 |
| E：稳定运营 | 资源预算、队列限流、存储生命周期、任务监控、备份恢复与版本回退 | 连续批次压测和故障恢复通过；无重复发布、原片可恢复 |
| F：商业产品 | 多项目/多角色、审计、模板版本、客户隔离、计费统计、交付 SLA | 使用合同和业务规则确定权限及保存策略后，通过客户试点验收 |

HeyGen 可作为独立可选的配音/数字人或补充素材适配器。用户的口播原片精剪应先保持真实表达和音画同步；外部生成需要独立的费用、素材权利和质量记录，不与本地编解码混为一个成功状态。

## 验收用例

1. 正在复制的大文件不进入剪辑；完成后只创建一次任务。中途断网再连，不覆盖不同内容的既有素材。
2. 未授权 API 请求被拒绝；素材或字幕路径不能越过投递箱，符号链接也不能绕过边界。
3. 合成音视频可通过完整 API 队列到达待审片状态，成片支持浏览器范围读取。
4. 输入损坏、无视频流、HDR/隔行等未支持条件产生可读错误，不能假装生成了合格成片。
5. 检查未通过不能确认；未确认不能发送；未配置企业微信不能进入发送流程。
6. 发布成功后的重复点击返回已有结果；发送响应丢失或服务中断时禁止自动重发。
7. 人工检查真实样片的开头、所有切点、口型同步、字幕、结尾和响度。合成测试不替代此项。

## 部署与数据

GPU 机器将项目、缓存和素材放在实际确认的大容量数据盘，避免占满系统盘。脚本 `scripts/doctor.py` 只做读取检查，不打印密钥值、不建立外部连接、不发送消息。它能帮助确认 Python、FFmpeg、依赖、可见 GPU 和剩余空间；不能据此认定远程部署或发布成功。

企业微信机器人地址、SSH 私钥和本机访问口令留在各自运行环境，不能写入 Git、Sites 静态文件、日志或成片元数据。前端访问远端 API 时，应使用精确 CORS 来源和 HTTPS；不把 Jupyter 会话口令当成业务系统 API 口令。

当前版本的长时守护、GPU 实际接入和企业微信实际投递都需要在用户提供的运行条件上完成验证。项目内的测试成功只证明已经覆盖的代码路径。
