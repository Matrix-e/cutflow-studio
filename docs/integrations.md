## 排队任务撤回（待部署更新）

此项代码尚未部署到 GPU，未做实机或专项测试。前端仅在 `/api/config` 返回 `queue_withdrawal_supported: true` 时提供入口，避免旧后端出现无效按钮。

- `POST /api/jobs/{id}/withdraw` 需要原工作台身份验证；只将正式制作任务的 `queued` 状态变为 `withdrawn`。与工作进程领取任务使用同一数据库写事务；已领取或已结束的任务返回 409，不终止进程、不改模型服务。缺失任务返回 404。
- 重复撤回同一条已撤回任务返回现有记录，不重复写事件；素材、讲稿、完整设置、来源、原作品关联和历史事件保留。计时停在撤回时刻，不列作制作成功或失败。
- `GET /api/jobs/{id}/draft` 可读取已撤回任务。新创作返回原草稿及原父作品、修改类型、参考作品编号；撤回任务本身不会被当作已完成的父作品。旧目录任务返回 `withdrawn_legacy` 及完整剪辑设置，避免丢失原片范围或字幕参数。读取不会重新入队。
- 继续编辑后由用户明确生成，以新的请求编号创建任务；旧记录仍为已撤回。原请求编号再次提交只返回原记录，不恢复制作。素材或参考作品缺失时，由原生成接口校验并提示处理。
- 自动观察器的 `watch-` 请求如果匹配同一素材版本及剪辑设置的已撤回任务，会复用撤回记录；不会因丢失提交响应而自动重建该任务。观察器保留已提交记录，并把撤回任务移出自动发布候选窗口。更换素材版本或自动剪辑参数属于新的观察器请求；撤回不等于关闭目录自动监测。
- 原视频换脸仍未开通；此次撤回更新不改变其模型商用授权要求。

## 当前素材入口

### 已选素材精确核对（待部署更新）

现有 `GET /api/assets` 保留 1,000 条列表上限，本轮未实现全目录分页。`GET /api/assets/video` 仍是播放接口，不用于元数据探测。新增的 `POST /api/assets/resolve` 只查询已选素材元数据；服务通过 `/api/config` 的 `asset_resolution_supported` 告知页面是否支持，旧服务不调用新接口。

请求体为 `sources` 数组，一次 1–12 个不同编号；编号沿用列表的 `source`（投递箱内的视频相对标识），每项最多 4,096 字符。输入须通过相对路径、格式和边界校验，不能指定其他目录或文件类型。使用与原素材接口相同的鉴权，技术测试等排除项不会成为可制作素材。网关原有请求体上限与超时仍然有效，不扩大文件读取范围。

每项返回 `found`、`not_found` 或 `unconfirmed`。`found` 仅附列表已有的名称、大小、修改时间、扩展名等必要元数据，不读取媒体内容或计算文件哈希，也不返回绝对路径或运行配置。只有素材根目录可确认、合法相对标识对应的文件明确不存在时才返回 `not_found`；权限、读取错误、范围受限、根目录状态不明等均为 `unconfirmed`。

页面按当前已选编号补齐元数据，与列表截断区分；连接、草稿或请求轮次变化会淘汰过期响应。查询失败不沿用旧的缺失结论，也不进入视频提交结果未知或重试流程。替换、上传和提交的原锁定规则保持，精确核对不会改变已提交任务。

这项更新只有源码和说明，未对真实素材调用接口，未运行专项测试、类型检查、构建或实机验收，未部署 GPU。

用户指定的本地目录为 `C:\Users\Administrator\Desktop\空间同步\BaiduSyncdisk\公司材料空间\视频素材`。程序只读原素材，不移动、不重命名、不删除。它可以和百度同步目录一起使用；复制文件完成后仍需等待至少 15 秒。

默认 GPU 目标目录为 `/root/autodl-tmp/cutflow-studio/inbox`，把代码、缓存和成片放在数据盘；不要占满系统盘。正式部署前应检查实际挂载及剩余空间。远端停机可能中断处理，不能把租用机器当作唯一备份。

## 同步器

`python -m studio.sync --dry-run --once` 只检查稳定素材并显示待同步清单，不联网。`python -m studio.sync` 常驻轮询，可用 `Ctrl+C` 停止。默认每 5 秒扫描一次，素材大小及修改时间连续 15 秒不变才入列。只支持视频、音频及 SRT 文件，跳过隐藏项、临时扩展名、软链接、Windows junction、缓存与输出目录。

同步前需由运维在本机进程环境配置：

| 变量 | 用途 |
| --- | --- |
| `CUTFLOW_INBOX` | 本地素材目录；可覆盖用户指定目录 |
| `CUTFLOW_SSH_HOST` | GPU 平台给出的 SSH 主机 |
| `CUTFLOW_SSH_PORT` | SSH 端口，默认 22 |
| `CUTFLOW_SSH_USER` | SSH 用户，默认 root；生产建议专用最小权限用户 |
| `CUTFLOW_SSH_KEY` | 本地 SSH 私钥绝对路径 |
| `CUTFLOW_SSH_KNOWN_HOSTS` | 已通过平台核对指纹的 known_hosts 文件 |
| `CUTFLOW_SSH_REMOTE` | GPU 收件目录 |

不接受未知主机、不自动信任服务器指纹，也不把密码或密钥写入源码。不要把 SSH 私钥或企业微信 Webhook 发到聊天里。密码保护的私钥需要部署方提供合适的密钥加载方式，当前最小实现不弹出密码框。

同步使用 SHA-256 去重，上传到 `.part` 文件，回读远端文件核验完整散列后才原子改名。远端文件名增加内容散列后缀，避免新素材覆盖已有待剪素材。仅在验证成功后持久记录同步完成。断网后指数退避重试；这一版失败时重传整个文件，尚未实现分块断点续传。原文件发生修改会产生新版本。失败遗留的 `.part` 文件不会被剪辑队列收取，由后续运维清理，不会自动删除。

在同一进程里，已同步且大小、修改时间不变的文件不重复全量散列。重新启动后会重新计算散列一次。极长时间暂停的复制不能仅凭时间戳判断完成；更稳妥的投递方式是先用临时扩展名复制，完成后原子改名为 `.mp4`。

## 企业微信内部群

当前目标是企业微信**内部群消息推送（群机器人）**。成片作为 MP4 文件附件发到配置的群。它不是客户群、客户朋友圈，也不等同视频号发布。

| 变量 | 用途 |
| --- | --- |
| `CUTFLOW_WECOM_MODE` | 设为 `webhook` |
| `CUTFLOW_WECOM_WEBHOOK` | 该内部群官方消息推送地址；仅在运行环境保存 |
| `CUTFLOW_PUBLISH_ENABLED` | 设为 `1` 才允许发送；默认关闭 |
| `CUTFLOW_DATA` | 发布台账目录，与主服务的数据目录保持一致 |

调用者还必须在审核通过后传入 `approved=True`。未配置、未开启、未审核通过均不能发送。只允许 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...` 目标，上传和发送均禁止重定向。系统不在响应、日志或页面中回显 Webhook、企业密钥或 access token。

先调用文件上传接口获得 `media_id`，再发一条 `file` 消息。代码按 20,000,000 字节作为保守上传上限，超限时提示另导出发布版，不会把高清母版偷偷降质。官方说明普通文件不超过 20 MB、须大于 5 字节，素材编号三天有效；每个推送目标每分钟最多 20 条。共享同一数据目录的进程按目标持久限流；若还有其他系统使用同一机器人，需要统一限流。[企业微信：消息推送配置说明](https://developer.work.weixin.qq.com/document/path/99110)

本地 SQLite 台账以任务编号持久去重。收到明确成功才记为已发布。发送超时、服务端结果不确定、发送中进程崩溃，均停止重发并要求核对群中是否已到达。机器人 API 不提供可靠的全程幂等键，不能承诺外部系统恰好发送一次；这版选择避免不确定时重复发送。对于上传失败或企业微信明确拒绝的请求，修复后可以手动重试。

自建应用适配代码作为可选接口保留，当前项目无需启用。它使用 `CUTFLOW_WECOM_CORP_ID`、`CUTFLOW_WECOM_SECRET`、`CUTFLOW_WECOM_AGENT_ID`、`CUTFLOW_WECOM_TO_USER`，仅支持明确员工 UserID，禁止默认 `@all`。视频保守上限为 10,000,000 字节。应用需要可见范围及可信 IP 等企业后台配置。[上传临时素材](https://developer.work.weixin.qq.com/document/path/90253)、[发送应用消息](https://developer.work.weixin.qq.com/document/path/90236)

以上官方页面于 2026-11-02 通过 HTTPS 直接读取确认；企业微信测试均使用模拟响应，没有向任何真实群或员工发送消息。

## 真实上线前仍需接通

1. 获取 GPU SSH 地址、端口与 SSH 密钥路径；在平台核对主机指纹。
2. 在 GPU 安装项目依赖并启动服务及素材监听任务。

4. 用真实口播素材评估删停顿、字幕准确率、语义完整性与声音衔接，验收后再扩大无人值守范围。

## GPU 源码上传

`python scripts/deploy_gpu.py --dry-run` 在 `data/deploy` 生成确定性源码包与逐文件散列清单，不连接远端。打包使用明确允许的源码目录，只包含程序、页面、测试、文档与依赖清单，不包含素材、运行台账、`.env` 或 SSH 密钥。检查后，在环境变量配置私钥路径与已核验的 known_hosts，再运行 `python scripts/deploy_gpu.py --upload`。

上传器默认使用上述用户提供的 SSH 入口。它以完整 SHA-256 核验 `.part` 文件后原子改名，放入 GPU 数据盘的新发布目录。它不自动执行远程命令，不覆盖运行中的版本，不创建或放宽任何主机信任。上传成功后，在 GPU 解压到新的目录，再运行 `bash scripts/remote-install.sh`。启动命令只绑定回环地址，并关闭 HTTP 访问日志，避免播放令牌出现在访问日志里。使用 SSH 端口转发访问控制台。

## 大视频交付边界

口播或课程母版很容易超过机器人文件限制。当前适配器会在上传前明确阻止超限文件，不会谎报发布成功，也不会自动降低母版画质。本版尚未实现自动双版本导出或可过期的私有下载链接。正式长视频交付建议保留高清母版，并增加独立的“企业微信发布版”大小预算或对象存储下载链接；这两条路线都需要实际时长、画质和企业访问权限验收。

## 不在聊天中填写 Webhook 的 GPU 配置入口

双击项目根目录的 `配置GPU企业微信.cmd`，在本机窗口粘贴内部群机器人地址。输入会隐藏；不支持隐藏输入的环境直接停止。程序使用已经配置的 GPU 专用密钥和已核验主机文件，把仅含机器人模式、地址和发布开关的 JSON 从内存通过 SFTP 写入 GPU 的 `data/wecom-config.json`，不保存本地 Webhook 副本，不输出密钥，不发送测试消息。

远端临时文件在写入任何配置内容前设置为仅所有者可读写（0600），回读校验后原子替换。服务会在下一次读取发布状态时加载配置，无需为更换机器人地址重启服务。显式的进程环境变量优先于文件；GPU supervisor 不应预设 `CUTFLOW_PUBLISH_ENABLED=0`，否则该值会覆盖文件。文件只允许设置三个发布字段，不能设置访问令牌、SSH 配置或自动发布开关。

配置成功后刷新 GPU 工作台，先试看并审核，再点击推送。这个配置入口不启用自动审核或自动发布。
