# v0.6.0 想法完善与模型部署

「帮我完善想法」把简短描述扩展成可编辑的创意方案。生成使用租用 GPU 上的 Qwen3-4B-Instruct-2507 语言模型，推理只读取预先准备的本地模型文件，不调用外部托管推理 API、不自动下载模型，也不在失败时返回模板冒充生成结果。

本文说明实现与验收方法，不证明某次部署或真实模型推理已经通过。

## 使用流程与执行边界

1. 在「开始制作」选择素材并写一句想法。可以不选素材先完善；有选材时只提供文件名作为上下文，最多 12 个。
2. 点击「帮我完善想法」。原文保留，页面显示排队或生成进度。点击该按钮不会创建视频任务。
3. 方案完成后预览受众、目标、开场、结构、视觉、声音和行动提示，核对假设，并编辑策划正文。
4. 明确采用后，想法框才替换为完整方案；可撤销回采用前文字。输入、素材或设置发生变化后，旧响应不能直接覆盖新内容。
5. 仍须点击「生成」才创建视频任务。查看实际制作方案、能力限制并审片；方案完成不等于视频已完成。

完善过程中只读取想法、可选风格和安全校验后的素材文件名，不解析视频、不听取原声。初次提交后，记录独立保存；之后素材删除不影响已有文字方案。模型可能补充假设，需按实际业务核对，不应将生成的分镜、数据、承诺或台词视为已核实事实。

采用后的文本末尾会追加唯一的 `【剪辑执行要求】`。制作引擎只解析这个区块中的支持项：目标时长、画幅、原声开关、停顿节奏、开头标题与额外配乐；显式高级选项优先。执行要求从原始输入解析生成，用于保留用户的硬约束，不直接采用模型自由生成的参数。前面正文里的分段秒数不会误改整片时长。

分镜、语义选亮点、新旁白、字幕、补镜头、复杂转场和调色仍是策划建议，当前不会自动执行。模型未观看素材，不能断言某段视频确实有方案中所需画面。「不加音乐」指不额外叠加背景音乐；原素材已有声音仍受原声开关控制。

## 独立请求与持久队列

想法服务使用 `CUTFLOW_DATA/ideas.sqlite3`，与视频任务、发布台账分开。单实例最多保留 4 条排队或处理中的请求，一个后台工作线程串行调用模型。完成记录和失败记录持久保留；服务重启后，原 `running` 请求标为明确的中断失败，原 `queued` 请求继续等待。

| 接口 | 行为 |
| --- | --- |
| `POST /api/ideas` | 提交或重放同一请求；快速返回，不同步等待推理 |
| `GET /api/ideas/{id}` | 查看状态与结果 |
| `POST /api/ideas/{id}/retry` | 明确重试失败记录；处理中重放不重复入队，成功记录不重做 |
| `GET /api/config` | `idea_refinement_supported` 表示配置、模型文件及指定 Python 文件就绪 |

以上接口均需要工作台鉴权。请求例子：

```json
{
  "request_id": "2d2afaf6-28b6-44e3-8f28-4694ab6d5268",
  "brief": "介绍汽车托管，做成30秒竖版，保留原声，不加背景音乐。",
  "sources": ["门店/讲解.mp4"],
  "style": "清晰可信"
}
```

`request_id` 必须为 UUID；`brief` 非空、最多 3000 字符；`sources` 可省略或为空，最多 12 个不重复、已同步的安全相对路径；`style` 可省略，最多 100 字符。只在初次提交时校验源文件路径，模型得到的是去除同步摘要后的文件名。不会读取或向模型传递机器绝对路径、令牌、视频字节。

响应格式为 `{"idea": {...}}`，其中 `id` 与请求 UUID 相同，`status` 为 `queued`、`running`、`succeeded` 或 `failed`，另有 `result`、`error`、`error_code`、`can_retry`、`attempts` 和时间戳。排队或处理中返回 202，重放已完成或失败的原请求返回 200。相同 UUID 配不同正文返回 409，队列已满返回 429，模型配置未就绪返回 503。

`result` 包含：

- `expanded_brief`：完整策划，最多 2400 字符，可在采用前编辑。
- `production_brief`：实际剪辑执行要求，最多 500 字符；追加标记后仍保证想法框不超过 3000 字符。
- `title`、`audience`、`goal`、`hook`、`visual_style`、`narration`、`music`、`cta`：结构化策划字段；旁白建议最长 800 字符，不表示已合成音频。
- `outline`、`assumptions`：内容结构与待核实假设的文字数组。

网络暂时中断时，优先查询原 UUID，或用完全相同的请求重放，避免另建请求。明确失败只能通过重试入口重新运行；原 POST 与 GET 不会自动重试。单次模型推理内部若草稿未通过内容校验，可使用同一已加载模型修订一次，两轮共享处理时限；修订仍不合格就明确失败，不返回模板替代。错误仅返回安全摘要，不回显模型原始诊断或环境凭据。

## 独立 GPU 模型部署

发布目录为 `/root/autodl-tmp/cutflow-studio/releases/v0.6-20261103-ideas-r2`。视频服务继续使用 `runtime/bin/python`；模型使用独立环境，避免升级模型依赖影响剪辑服务：

| 路径或变量 | 用途 |
| --- | --- |
| `/root/autodl-tmp/cutflow-studio/idea-runtime/bin/python` | 独立 GPU 推理 Python |
| `/root/autodl-tmp/cutflow-studio/models/Qwen3-4B-Instruct-2507` | 完整本地模型、分词器和权重 |
| `requirements-ideas.txt` | 模型环境依赖，与视频服务 `requirements.txt` 分离 |
| `CUTFLOW_IDEA_PYTHON` | 指向模型环境 Python 的绝对路径 |
| `CUTFLOW_IDEA_MODEL_DIR` | 指向模型目录的绝对路径 |

部署步骤：

1. 将完整配套源码放入新发布目录，保留共享 `data` 与 `inbox`。从早期版本升级时，先升级 GPU 观察器再开放 `library` 上传，见 [创作部署顺序](creation-workflow.md#部署顺序)。
2. 在数据盘准备独立 `idea-runtime`，安装适配现有驱动的 CUDA PyTorch 构建，然后在该环境安装发布目录的 `requirements-ideas.txt`。该清单不包含 PyTorch，不能仅安装清单就假定 CUDA 已可用；不要改动既有视频服务环境或驱动来凑依赖。
3. 事先准备完整 Qwen3-4B-Instruct-2507 模型，包括配置、分词器、权重与分片索引。程序只做本地读取；推理时缺少文件会明确失败，不会临时下载。
4. 在启动远端守护程序的环境设置下列变量。标准路径存在时，`scripts/run_gpu.py` 也会自动补齐；显式环境变量优先。单独运行 API 时需自行设置。

```sh
export CUTFLOW_IDEA_PYTHON=/root/autodl-tmp/cutflow-studio/idea-runtime/bin/python
export CUTFLOW_IDEA_MODEL_DIR=/root/autodl-tmp/cutflow-studio/models/Qwen3-4B-Instruct-2507
```

5. 通过既有受控流程停止旧守护程序、启动新版本，并核对 API 实际版本及运行目录；不要并行运行两个共享数据目录的服务。更新并重启本机网关、刷新网页，使前后端和执行区块解析保持同一版本。
6. 检查 `idea_refinement_supported`，然后执行下述真实模型验收。该字段只检查配置与文件存在性，不验证 CUDA、Python 依赖可导入、模型权重可加载或输出质量；适配器的 `runtime_verified: false` 也不能作为验收结果。

每次生成启动独立子进程，单次加载模型，结束后退出，不在视频 API 进程内导入模型运行库或保留模型显存。服务停止会传递取消信号；超过 180 秒硬时限会终止并回收子进程，标记失败，不自动重试。当前实现要求可用 CUDA GPU，加载前检查至少 10 GiB 空闲显存，并设置进程显存上限为总量的 65%；这些是资源保护条件，不保证与所有并行任务共存。资源不足时保留原文并返回明确失败。

## 验收步骤

已有定向自动测试记录：14 项想法 API/队列测试，加服务与创作回归及模型适配测试，联合 65 项通过。它们验证幂等、队列上限、串行执行、取消、重启恢复、安全错误、结果长度和服务生命周期；受控模型替身不能证明真实模型质量。

真实部署应分别记录以下证据：

1. **环境与进程：** 记录实际发布版本、模型标识、GPU 可用性；生成前后查看推理进程和显存占用，确认子进程退出，不遗留常驻模型。诊断记录不包含访问令牌。
2. **三类输入：** 分别输入简短汽车托管介绍、明确“30 秒竖版、保留原声、不加音乐”的约束、含素材文件名的栏目想法。核对方案有针对性，未虚构商业承诺或已看过素材，执行要求保留硬约束。
3. **浏览器操作：** 预览、修改、采用、撤销；生成中修改原文或选材，确认旧结果不能覆盖新输入。确认失败不丢原文，刷新后能核对原请求。
4. **隔离与恢复：** 完善想法前后视频任务数量不变；重复提交不多开推理；模拟失败只在明确重试后重新执行；重启不把中断请求伪报成功。
5. **执行边界：** 采用方案后点击生成，核对只执行区块内支持项。正文分镜中的局部秒数不改变整片时长，新旁白与字幕仍显示为未自动执行；观看成片确认声音、标题、切点和时长。

实际模型成功、内容质量、显存释放和网页流程应保留各自结果。配置就绪、自动测试通过与任务返回成功都不能单独证明商用成片质量。
